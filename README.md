# Автоматизация ML-пайплайна на Apache Airflow

Оркестрация ML-пайплайна: обучение модели и генерация предсказаний на новых данных в виде двух связанных задач Airflow DAG, запускаемого в Docker.

Учебный проект: пример построения простого MLOps-конвейера с зависимостью задач.

## Как устроен пайплайн

DAG состоит из двух последовательных задач:

1. **`pipeline`** — загрузка тренировочных данных, обучение модели, оценка качества и сохранение обученного пайплайна на диск (`pickle`).
2. **`predict`** — загрузка сохранённой модели, обработка тестовых данных из `data/test`, формирование предсказаний и сохранение результата в CSV в `data/predictions`.

Задача `predict` стартует только после успешного завершения `pipeline`.

## Структура репозитория

- `dags/` — DAG для планировщика Airflow (`hw_dag.py`).
- `modules/` — логика задач (`pipeline.py` и `predict.py`).
- `data/` — входные данные и результаты предсказаний.
- `.gitignore` — исключает служебные файлы и локальные датасеты.

## Стек

Python · Apache Airflow · Docker / Docker Compose · scikit-learn · pandas · NumPy

## Статус

Учебный проект. Пайплайн был запущен и отработан в рамках курса на локальном окружении Airflow в Docker. Актуальность запуска после обновлений Airflow и Docker не перепроверялась, поэтому готовая конфигурация окружения и пошаговая инструкция в репозиторий не включены. Описание архитектуры и логики задач отражает реализованный DAG.

## Ограничения

- Нет тестов, мониторинга и обработки ошибок за пределами стандартных механизмов Airflow.
- Модель и предсказания сохраняются на локальный диск, без реестра моделей и версионирования.
- Датасеты не входят в репозиторий.
